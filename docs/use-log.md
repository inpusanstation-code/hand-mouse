# 쓰면서 배우기: 실행 기록 → 동작별 확인 → 자동 학습 (2026-11-11)

목표(사용자 제안): 처음에는 빠른 방식(규칙·MLP·자세 비교)으로 바로 쓰고, 쓸 때마다 그 동작의 앞뒤를 기억했다가 TCN을 틈틈이 자동으로 학습시켜 오탐지를 줄인다.

```
명령 실행 ─→ 앞 2초~뒤 1.5초 관절 + 두 모델의 "막았을지" 기록 (1단계, logs/use_events)
   │                    │
   │ F = 원하지 않음     ├─→ 동작별 집계 → 자격을 얻은 동작만 그 모델이 막음 (2단계, gate.json)
   │                    └─→ 손이 30초 안 보이면: 기록을 표본으로 가져와 "내 모델" 학습 → 검사 → 교체 (3단계)
   └────────────── 교체된 모델이 다시 지켜봄 ←──────────────┘
```

## 사용자가 정한 흐름 (2026-11-11, 이 문서의 기준)
1. [말·글로 연결 (AI)]에서 새 자세를 등록한다(가르친 손 모양 MLP + 그 자세의 복합 동작 `comp_*`, 또는 [새 동작 등록]).
2. 그 자세를 거듭 쓴다. 빠른 모델(MLP·자세 비교)이 바로 알아본다.
3. 쓸 때마다 앱이 그 실행의 앞뒤 관절을 저장해 TCN 학습 자료로 쌓는다(1단계 기록, `source` = `binding`의 `comp_*` / `registered`).
4. 한 자세의 사용 사례가 20번 쌓이면 앱이 스스로 TCN 학습을 시작한다. **첫 화면 제목 줄 아래 초록 띠**가 지금 무엇을 하는지 알려 준다: "'이름' 사용 사례를 모으는 중 12/20 · 20번이 되면 TCN 학습을 자동으로 시작해요" → "자동 학습 · 학습 중… 25/72" → 결과 → "TCN이 배운 동작: 이름".
5. 학습이 검사를 통과하면 그 자세의 **전용 확인 모델**(`src/online/verifier.py`)이 생기고, 그때부터 빠른 모델이 "그 자세"라고 할 때마다 TCN 쪽이 앞 0.5초의 움직임을 보고 한 번 더 확인한다. 아니라고 하면 명령을 실행하지 않는다.
6. 계속 쓰면 사례가 20번 더 쌓일 때마다 그 자세의 확인 모델을 다시 검사하고(가장 최근 날의 사용으로) **모든 사례로 다시 학습**한다. 쓸수록 자료가 늘고, 확인 모델이 틀리게 막았던 사용(아래 "세 번째 시도")도 다음 학습의 정답으로 들어간다.

구현: 사례 수 `QtRuntime._use_pending`(앱을 다시 켜도 `use_import.pending_counts`가 기록에서 다시 셈), 안내 문구 `Snapshot.learn_note` → `QtDashboard.learnBanner` → `dashboard.qml`의 `learnBanner`, 가져오기 `src/online/use_import.py`(20번 전에는 기록에 그대로 둠), 학습 `verifier.train_verifiers`(`scripts/online_update.py --use-events`가 내 모델 학습 뒤에 부름), 앱에서 읽기 `OnlineGate.verifiers`, 확인 `QtRuntime._use_allows`.

### 전용 확인 모델 (사용자 결정, 2026-11-11)
- 내 모델(`production.pt`)은 **읽기만 한다.** 그 인코더가 낸 임베딩 위에 자세마다 작은 머리(64 → 32 → 1, "이 자세인가 아닌가")를 따로 학습한다. 기존 동작의 인식은 구조적으로 변하지 않는다.
- 정답: 그 자세의 사용 사례(실행 앞 0.4초~뒤 0.15초). 오답: 저장소의 다른 모든 표본(안내 녹화의 모든 동작과 쉬기, "원하지 않음" 표시한 실행, 다른 가르친 자세).
- 검사(사용자 결정으로 2026-11-11에 바꿈): **가장 최근 날의 사용**을 따로 두고 그 전날들의 사용으로 학습한다(최근 날이 4번 미만이면 그 앞날까지 따로 둠, 학습용은 10번 이상). 검사 세션의 오답 창도 따로 둔다. 따로 둔 사용의 80% 이상을 인식(기준 넘는 창 3개 연속, 앱과 같은 조건)하고 오답 창 중 기준을 넘는 것이 2% 이하일 때만 저장한다. 기준(0.5~0.9)은 그 한도 안에서 인식이 가장 좋은 값. 떨어지면 아무것도 바뀌지 않고, 사례가 더 쌓이면 다시 학습한다.
  - 처음에는 같은 날 사용 5번 중 1번을 따로 두었는데, 구간 비교 실험에서 다른 날의 수치가 훨씬 낮게 나와 바꿨다.
  - **하루만 쓴 자세는 확인 모델이 생기지 않는다**(`waiting`, `one_day`). 첫 화면에 "사용 사례 N개 저장됨 · 다른 날에도 쓰면 그날 사용으로 검사한 뒤 TCN 확인을 시작해요"가 뜨고, 다른 날에 4번 쓰면 자동으로 검사한다(`verifiers/status.json`, `QtRuntime._use_waiting`).
  - 합격하면 실제로 쓰는 모델은 따로 둔 날까지 포함한 모든 사용으로 다시 학습한다(기준은 합격한 값). 가장 최근 사용이 내일의 사용과 가장 비슷하기 때문이다.
- 저장: `data/online/verifiers/<키 해시>.json`(가중치, 기준, 검사 수치, 학습한 인코더 표시). 인코더가 바뀌면 불러오지 않고 다시 학습한다.
- **세 번째 시도:** 확인 모델이 막으면 상태 줄에 알리고, 8초 안에 세 번째로 같은 자세를 하면 통과시킨다(`forced: true`로 기록, 다음 학습의 정답). 빠른 모델과 확인 모델이 어긋날 때 사용자가 갇히지 않게 하는 장치다.
- 끄기: `"taught_verifier_enforce": false`(막지 않고 지켜보기만).

**실측(`data/online` 복사본, 실제 학습 프로세스, 아래 표와 같은 자료 30번, 검사를 바꾸기 전의 "5번 중 1번" 방식):** 따로 둔 사용 6/6 인식, 오답 창 중 1.6%가 기준(0.9)을 넘음 → 저장. 내 모델의 클래스·가중치는 그대로. 자료가 한 세션의 쓸기 동작 녹화라서 새 검사(최근 날)로는 잴 수 없다: 지금 방식이면 이 자료는 "하루치뿐"으로 대기한다. 여러 날에 걸친 실사용 기록에서의 수치는 아직 없다.

### 더 긴 구간을 보게 하면 나아지는가 (2026-11-11, `scripts/verifier_window_compare.py`, 결과 `logs/verifier_window_compare.json`)
사용자 질문: "앞뒤 2~3초를 잡아 두면 맥락 이해에 도움이 되지 않을까? 1초는?" 저장은 앞 3초·뒤 2초로 늘렸고, 여기서는 **확인 모델이 보는 구간**을 늘려 보았다. 같은 머리에 지금 임베딩만 준 것(0.5초)과, 0.5초·1초·1.5초 전 임베딩을 함께 준 것(1초, 2초)을 비교했다.

- 자료: 실사용 기록이 아직 없어 안내 녹화 42개로 대신했다. 동작 하나를 "가르친 자세"로 보고 그 `do` 구간을 정답, 손이 보이는 나머지 프레임을 오답으로 했다(그 동작 앞뒤 0.7초는 정답도 오답도 아님). 인코더의 검사 세션 11개 녹화로 시험(한쪽에만 있는 동작은 녹화 안에서 시간으로 60/40).
- 수치: 시험 오답 창의 1%만 기준을 넘는 기준에서 인식한 반복 비율(창 3개 연속), 씨앗 5개 평균 ± 최대·최소 차의 절반. 기준을 시험 자료에서 골랐으므로 길이끼리의 비교용이지 절대 성능이 아니다.

| 동작 (시험 반복 수) | 0.5초 | 1초 | 2초 |
|---|---|---|---|
| 엄지+중지 (39) | 0.78 ± 0.09 | 0.87 ± 0.06 | **0.91 ± 0.05** |
| 엄지+약지 (44) | 0.62 ± 0.06 | 0.63 ± 0.07 | 0.73 ± 0.06 |
| 엄지+검지 (120) | **0.58 ± 0.03** | 0.46 ± 0.02 | 0.46 ± 0.03 |
| 손바닥 옆 (30) | 0.68 ± 0.02 | 0.73 ± 0.02 | 0.68 ± 0.02 |
| 쓸기 (12, 인코더가 모르는 동작, 시간 분할) | 1.00 | 1.00 | 0.98 ± 0.04 |
| 엄지척 (23) | 0.59 ± 0.33 | 0.34 ± 0.30 | 0.58 ± 0.43 |
| V 사인 (10) | 0.40 ± 0.50 | 0.40 ± 0.50 | 0.26 ± 0.50 |
| 평균 | 0.66 | 0.63 | 0.66 |

- **결론: 이 자료에서는 긴 구간이 일관되게 낫지 않다.** 엄지+중지는 2초가 분명히 낫고(0.78 → 0.91) 엄지+약지도 조금 낫지만, 엄지+검지는 분명히 나빠지고(0.58 → 0.46) 나머지는 편차 안이다. 평균은 같다. 그래서 확인 모델은 0.5초 그대로 둔다.
- 왜 그럴 수 있는가(추정): 안내 녹화는 "준비 → 동작 → 쉬기"가 늘 같은 순서라, 긴 구간이 배우는 것이 손의 맥락이 아니라 녹화 일정일 수 있다. 실사용 기록(같은 자세가 뜻한 때와 뜻하지 않은 때)이 쌓여야 맥락이 도움이 되는지 제대로 잴 수 있다. 그때 이 스크립트를 실사용 기록용으로 고쳐 다시 잰다.
- 함께 드러난 것: **다른 날 녹화에서의 수치가 낮다**(손바닥 옆과 엄지+검지는 반복의 90%를 인식하려면 오답 창의 15% 이상이 기준을 넘는다). 당시 확인 모델의 합격 검사는 같은 날 사용 중 5번에 1번을 따로 두는 방식이라 이보다 후했다. 그래서 "가장 최근 날의 사용"을 따로 두는 검사로 바꿨다(위 "전용 확인 모델"의 검사 항목).

### 좌클릭·우클릭의 확인 모델 (사용자 결정, 2026-11-11)
사용자: "좌우클릭 판정은 카메라 각도에 따라서 pinch 위치가 아니라도 pinch 위치인 것처럼 보여서 오판정이 자주 난다" → 깊이 확인(오판의 약 30%만 걸러짐, 진짜 클릭 5% 손실)보다 **시간 흐름으로 판단**하기로 하고, "좌우 클릭의 맥락 데이터도 모아서 TCN으로 자동학습"하게 했다.

- 클릭의 앞 3초·뒤 2초 관절과 F 표시는 1단계에서 이미 기록되고 있었다. 빠져 있던 것은 그 기록으로 배우는 클릭 전용 모델이다. 가르친 자세와 같은 **전용 확인 모델**을 클릭에도 만든다. 키는 `<동작>:<모델 라벨>`(`use_import.click_key`, 2단계의 `gate_key`와 같음): 가상 손은 `left_click:thumb_index`·`right_click:thumb_index_middle`, 규칙 엔진은 `left_click:thumb_middle`·`right_click:thumb_ring`.
- 정답: 표시 안 한 클릭의, 클릭 순간까지의 창(실행 앞 0.15초; 클릭은 일어나는 순간에 판정하므로 그 뒤의 창은 정답에도 오답에도 넣지 않는다). 오답: **"원하지 않음"으로 표시한 클릭**과 저장소의 다른 모든 표본. 같은 손가락 핀치의 안내 녹화와 끌기 시작은 오답에서 뺀다(같은 손짓이다).
- 검사·저장·세 번째 시도는 가르친 자세와 같다(가장 최근 날의 클릭으로 검사 → 하루만 쓴 날에는 `waiting`/`one_day`). 표시한 클릭이 늘어도 다시 학습한다(`Verifier.uses` = 클릭 수 + 표시 수).
- 앱: `QtRuntime._use_enforce`가 클릭이 시작될 때 그 클릭의 확인 모델에 묻고, 아니라고 하면 실행하지 않는다(8초 안 세 번째 시도는 통과, `forced`). 끄기 `"click_verifier_enforce": false`. 클릭 40번(가르친 자세의 두 배: 클릭은 훨씬 잦다)이 쌓이면 학습을 요청하고, 첫 화면 띠에 "좌클릭 사용 사례를 모으는 중 n/40 · 잘못 눌린 클릭은 5초 안에 F를 누르면 '아님'으로 배워요"가 뜬다.
- 모델에 클래스가 없는 손짓의 클릭(가상 손 우클릭 = `thumb_index_middle`)도 이제 저장한다(전에는 버렸다). 내 모델의 클래스로는 넣지 않는다(`extra.click`, `update_job`에서 제외). 전에 읽은 기록 파일은 한 번 다시 읽어 빠진 클릭을 가져온다(`use_import.json`의 `clicks` 표시).
- **이 PC 실측(2026-11-11, `data/online`과 기록의 복사본):** 좌클릭 170번·우클릭 40번(39번은 되살린 것)이 자료로 잡혔고, 표시한 좌클릭은 4번뿐이다. 둘 다 `waiting`/`one_day`: 내일 이후 4번 이상 쓰면 그날 클릭으로 검사한다. **각도 때문에 잘못 눌린 클릭을 실제로 얼마나 막는지는 아직 잴 수 없다**: 오답의 핵심인 "표시한 클릭"이 거의 없기 때문이다. F를 눌러 준 만큼만 배운다.
- 시험 `tests/test_click_verifier.py`. 실제 카메라로 확인 모델이 생긴 뒤의 동작은 아직 못 봤다.

### 처음 시도: 내 모델에 새 클래스로 넣기 (버림)
**실측(2026-11-11, `data/online` 복사본, 실제 학습 프로세스): 이 방식으로는 새 자세가 TCN에 들어가지 못했다.** 기본 모델이 모르는 동작(`swipe_tab_left` 녹화 30회)을 가르친 자세 `comp_demo`의 사용 30번으로 넣고 한 번 학습시켰다.

| 학습 설정 | 결과 | 기존 동작(검사 세션 246회) | 오작동 | 새 동작(따로 둔 1회) |
|---|---|---|---|---|
| 기본(3회 반복, lr 3e-4, 분류기만) | 탈락 | 212 → 200 | 94 → 54 | 0/1 |
| 12회 반복 | 탈락 | 212 → 153 | 94 → 87 | 1/1 |
| 12회, lr 1e-3 | 탈락 | 212 → 167 | 94 → 90 | 1/1 |

| 12회, lr 1e-3, 균형 재생 | 탈락 | 212 → 187 | 94 → 111 | 1/1 |

새 동작을 배울 만큼 학습하면 기존 동작(엄지+검지, 손바닥 옆)을 잊고, 덜 학습하면 새 동작을 못 알아본다. 검사가 모두 걸러 냈으므로 쓰는 모델은 바뀌지 않았다. 그래서 가르친 자세의 사용은 이제 내 모델 학습에 넣지 않고(`update_job`의 `_taught` 제외) 위의 전용 확인 모델로만 간다.

## 1단계: 기록 (`src/use_log.py`)
- 손 명령이 실행될 때마다 앞 3초 ~ 뒤 2초의 관절(화면 좌표 + 3D; 2026-11-11 사용자 요청으로 앞 2초·뒤 1.5초에서 늘림, 실행 하나에 약 200 KB)을 `logs/use_events/<날짜>-<시각>-<pc>.jsonl`에 쓴다. 영상·창 제목·명령 내용(입력 글자, 여는 주소)은 없다. 관절을 뺀 같은 기록이 옆의 `.idx`에 있다(집계용). 저장은 별도 스레드, 폴더는 300 MB를 넘으면 오래된 파일부터 지운다.
- 기록되는 실행(`source`):
  | source | 무엇 | key |
  |---|---|---|
  | `rule` | 규칙·가상 손의 클릭, 우클릭, 스크롤 잡기 시작, 끌기 시작, 창 전환, 바탕화면 | 동작 이름 (`left_click` 등) |
  | `binding` | 연결한 명령(복합 동작, 이어 하기, 손 모양 그리기, 모션, 사인 바꿔 연결) | 바인딩 키와 명령 종류만 |
  | `registered` | 등록한 새 동작의 명령 | 동작 이름 |
  | `pointer` | 검지 포인터 모드의 클릭 | 동작 이름 |
- "원하지 않음" 표시: 실행 뒤 5초 안 **F**(`f_key`), 또는 실행 직후 일시정지(`user_cancelled`). 가장 최근 실행 하나에만 붙는다.
- 지켜보는 모델 둘: 기존 모델(`models/gesture_tcn.onnx`, 기록의 `shadow`)과 내 모델(`data/online/versions/production.pt`, `shadow_online`). 손짓 확인이 꺼져 있으면 막지 않는 복사본으로 돈다(기존 모델 프레임당 약 0.8 ms 실측). 실행마다 "막았을지"(`would_pass`, 이유, 모델 파일 표시 `model`)를 남긴다.

## 2단계: 자격을 얻은 동작만 막기 (`src/use_gate.py`, `QtRuntime._use_enforce`)
- 집계 단위는 `<동작>:<모델 라벨>`(예: `right_click:thumb_ring`, 가상 손의 `left_click:thumb_index`), `source`가 `rule`인 실행만.
- 자격: 표시한 실행 20번 이상·표시 안 한 실행 20번 이상을 그 모델이 판정했고, **표시한 것의 50% 이상을 막았을 것**이며 **표시 안 한 것은 5% 이하만 막았을 것**. 두 모델이 다 자격이 있으면 표시한 것을 더 많이 막는 쪽.
- 세는 조건: 이 PC의 기록, 지금 쓰는 모델 파일이 낸 판정, 그 동작을 아직 막지 않던 때의 실행(막기 시작한 뒤 실행된 것은 모두 통과한 것이라 아무것도 말해 주지 않는다), 손짓 확인이 그 모델로 켜져 있지 않던 때.
- 결정은 앱이 스스로 한다: 시작할 때, 손이 30초 안 보이고 새 실행이 20번 쌓였을 때, 모델이 바뀌었을 때. 결과는 `logs/use_events/gate.json`. 새로 자격을 얻으면 상태 줄에 "이제 학습 모델이 확인해요: …"가 뜬다.
- 막는 방식: 그 동작이 **시작되는 순간** 해당 모델의 판정이 "아님"이면 실행하지 않고 상태 줄에 알린다(잡기·끌기는 그 손짓이 끝날 때까지). 기록이 센 판정과 같은 판정이라, 측정한 비율이 그대로 적용된다.
- 모델 파일이 바뀌면(자동 학습으로 교체, 새 TCN 학습) 그 모델의 자격은 사라지고 새 파일의 판정이 다시 쌓여야 한다.

## 3단계: 기록으로 자동 학습 (`src/online/use_import.py`, `update_job.run_update(use_events=…)`)
- 시작 조건(런타임이 요청, 화면 쪽이 학습 프로세스 시작): **가르친 자세 하나의 사용 사례 20번 이상**, 또는 "원하지 않음" 표시 5번 이상 + 마지막 실행에서 6초 지남(표시가 들어올 시간) + 지난 요청에서 10분 지남 + `online_learning_enabled` + 기본 모델이 있음(`data/online/encoder.json` 또는 `versions/production.pt`). 손이 안 보일 때까지 기다리지 않는다(학습은 낮은 우선순위의 별도 프로세스).
- 기록 → 표본(`data/online`, 같은 기록은 두 번 들어가지 않음):
  | 기록 | 표본 | 정답 종류 |
  |---|---|---|
  | 표시한 실행 | 실행 앞 0.5초~뒤 0.15초를 `none` | `validated_pseudo_label` (사람이 "아님"이라 했지만 무엇인지는 고르지 않음) |
  | 표시 안 한 실행, 모델이 아는 동작 | 실행 앞뒤 0.15초를 그 동작 | `pseudo_labeled_candidate` (아무도 확인 안 함) → 학습 때 3개 창 중 1개만 |
  | 가르친 자세의 명령(`comp_*`, 등록 동작), 표시 안 함 | 실행 앞 0.4초~뒤 0.15초를 그 자세(라벨 = 키) | `pseudo_labeled_candidate`. 20번 모이기 전에는 기록에 그대로 둔다. 내 모델이 아니라 그 자세의 전용 확인 모델만 학습한다 |
  | 이어 하기·손 모양 그리기·모션, 가상 손 주먹 | 가져오지 않음 | 모델이 보는 0.5초 창에 담기지 않거나 클래스가 없다 |
- 실행 사이의 조용한 구간은 `none`으로 쓰지 않는다. 규칙이 놓친 진짜 동작(다른 세션 FRR 0.44 실측)이 "아무것도 아님"으로 학습되기 때문이다.
- 학습·검사·교체·되돌리기는 기존 그대로다: 후보는 학습에 안 쓴 세션에서 기존 모델보다 나빠지지 않아야 교체되고, 다음 학습을 시작할 때 뒤처졌으면 자동으로 되돌린다. [학습하기] 단추는 예전처럼 정정·확인 데이터만 쓴다(자동 학습만 기록을 쓴다).
- 직접 돌리기: `python scripts/online_update.py --use-events logs/use_events` (`--no-weak`: 표시한 실행만).

## 한계
- 표시 안 한 실행을 맞는 동작으로 센다. 틀렸는데 표시하지 않은 실행은 (1) 모델에 불리하게 세어지고 (2) 약한 정답으로 학습에 들어간다. F를 눌러 주는 만큼만 정확해진다.
- 막기 시작한 동작은 비교가 더 쌓이지 않는다. 다시 재려면 `"use_gate_auto": false`로 잠시 끄고 쓴다. "막혔는데 사실 하려던 동작"을 표시하는 키는 아직 없다.
- 확인 모델이 보는 것은 실행 직전 0.5초(15프레임)의 손 움직임이다. 그보다 긴 맥락(몇 초 전에 무엇을 하고 있었는지, 어떤 창이 떠 있는지)은 보지 않는다. 기록에는 앞 3초~뒤 2초가 있으므로, 확인 모델이 더 긴 구간(예: 1~2초)을 보게 하는 실험은 쌓인 기록으로 할 수 있다(아직 안 함).
- 확인 모델은 막기만 한다. 빠른 모델이 놓친 자세를 살려 주지는 않는다.
- 확인 모델이 막은 시도는 기록되지 않는다(세 번째 시도로 통과한 것만 남는다).
- 규칙이 놓친 동작은 기록되지 않는다. 인식률은 이 흐름으로 좋아지지 않는다(오탐지만 줄인다).
- 가상 손 모드에서 막힌 클릭도 `logs/virtual_clicks`에는 클릭으로 남는다(그 기록이 먼저 쓰인다).
- 표본의 화면 비율은 720/1280으로 가정한다(다른 비율의 카메라에서는 기록에 비율을 넣어야 한다).

## 클릭의 세부 분류와 여러 확인 모델 (2026-11-11)
사용자: "좌클릭은 예전 데이터라서 지금 가상 손 모드와 다른 좌클릭일 것 같다. 어떤 모드의, 어떤 식의 좌클릭인지도 세부 분류해서 TCN이 적절하게 학습하게", "필요하다면 멀티 TCN을 구성해서 앱이 알아서".

- **실제 자료 확인:** 그때 저장돼 있던 좌클릭은 예전 모드 것이 아니었다. 기록(`logs/use_events`)의 좌클릭 238번이 전부 2026-11-11 10~14시, 가상 손 모드의 엄지+검지 클릭이었다. 다만 그 안에 한 번 클릭과 더블클릭의 두 번째 클릭이 섞여 있었다.
- **분류 (`use_import.click_key`, `click_name`):** 키 = `<동작>:<모델 라벨>[:double]`.
  - 모드와 손가락은 모델 라벨에 들어 있다: `thumb_index` = 가상 손 엄지+검지(좌클릭), `thumb_index_middle` = 가상 손 엄지+검지+중지(우클릭), `thumb_middle` / `thumb_ring` = 손바닥 모드(규칙)의 좌·우클릭. 화면 이름에 그대로 나온다("좌클릭 · 가상 손 (엄지+검지)").
  - 방식: 더블클릭의 두 번째 클릭은 `:double`. 직전 0.5초에 손이 쉬고 있던 것이 아니라 첫 클릭이 들어 있어서 한 번 클릭과 다른 자료다. 앱이 실행할 때 `click_kind`로 기록하고, 그 전에 쌓인 기록은 앞 좌클릭과의 간격(0.7초 이내)으로 구한다. 이미 저장된 표본도 다음 가져오기 때 기록에서 종류를 찾아 붙인다(`split_click_kinds`).
  - 검지 포인터 모드의 클릭은 `source`가 `pointer`라 여기에 들어오지 않는다. 끌기는 다른 동작(`drag_hold`)이라 클릭 모델과 섞이지 않는다.
- **여러 모델을 앱이 스스로 구성:** 확인 모델은 원래 "자세 × 손 방향"마다 하나씩이고(같은 인코더 위의 작은 머리들), 이제 클릭도 "동작 × 모드 × 방식"마다 하나다. 한 종류의 사례가 20번이 안 되면 그 종류는 따로 두지 않고 기본 클릭 모델과 함께 학습하며, 실행 중에도 기본 모델에게 묻는다(`QtRuntime._click_model`). 20번을 넘기면 다음 학습 때 그 종류의 모델이 따로 생긴다. 사람이 정할 것은 없다.
- **다시 분류한 결과(이 PC):** 좌클릭 · 가상 손 한 번 169개(+원하지 않음 4), 더블클릭의 두 번째 51개(+원하지 않음 1), 우클릭 · 가상 손 91개. 두 번째 클릭이 20번을 넘어 다음 학습부터 모델이 따로 생긴다(둘 다 하루치라 검사는 다른 날 사용 뒤).
- 아직 나누지 않은 것: 손이 향한 방향(자세 쪽은 방향별로 나뉘지만 클릭 기록에는 방향이 없다), 클릭 직전의 손 속도. 필요해지면 같은 방식으로 종류를 늘릴 수 있다.
