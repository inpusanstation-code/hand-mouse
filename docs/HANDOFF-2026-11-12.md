# 인수인계 (2026-11-11 저녁 ~ 11-12 새벽 세션, PC `pc-rtx3060`)

다음 작업자(AI)가 이어받기 위한 요약이다. 날짜별 근거와 수치는 저장소의 `CLAUDE.md` 각 절에 있고, 이 문서는 "무엇이 됐고, 무엇을 확인 못 했고, 다음에 무엇을 할지"만 모았다.

## 1. 사용자의 목표 (원문 요지)

"자료가 적정량이 차면 pt와 onnx를 앱이 알아서 자동으로 학습시키고, 앱이 꺼지면 중간에 멈췄다가 다시 켜면 이어서 조금씩 학습을 완료하면서, 쓰면 쓸수록 모델 스스로 진화하는 모습."

- 모델은 둘이다. 헷갈리기 쉬우니 사용자에게 설명할 때 구분할 것.
  - `models/gesture_tcn.onnx`: "손짓 확인 (TCN)"이 쓰는 기본 손짓 모델(엄지+검지 등 8종). 안내 녹화로 학습해 내보낸 것.
  - `data/online/*.pt`: 쓰면서 배우는 쪽. 기본 모델(`encoder.pt`), 내 모델(`versions/production.pt`), 가르친 자세·클릭마다의 확인 모델(`verifiers/`).
- `data/`와 `logs/`는 git에 없다. 새 폴더·다른 PC에는 따라오지 않는다(아래 4절).

## 3. 자동 학습의 지금 동작

- **모으기**: 손 명령이 실행될 때마다 앞 3초·뒤 2초 관절을 `logs/use_events/`에 기록.
- **검토**: 가르친 자세(방향별) 20개, 클릭 40개가 모이면 카드가 "검토 필요". 사용자가 [통과]/[오탐지]. 판정은 `logs/use_events/reviews.json`. 통과만 그 동작의 예시, 오탐지는 "이 동작이 아님" 예시.
- **pt 학습**: 통과 수가 필요 수에 차면 자동 회차(`scripts/online_update.py`, 이 PC 첫 회차 53초). 끊기면 다음 시작 때 회차를 처음부터 다시. 확인 모델은 최소 이틀치 사용이 있어야 생긴다.
- **onnx 후보 학습**: 판정한 사례가 처음 50개, 그 뒤 30개마다, 마지막 후보에서 1시간 뒤(`scripts/onnx_auto_update.py`, 이 PC 353초). 지금 모델은 그대로 두고 `models/candidate/`에 후보와 비교를 만든다. 사용자가 [새 모델 확인]에서 [적용]해야 바뀐다.
- 적정량은 전부 **출발점**이다(측정으로 정한 것이 아님). 카드에 n/필요 수로 보인다.

## 4. 이 PC의 상태와 올린 사본

올린 사본: `field-logs/2026-11-11-pc-rtx3060/` (85 MB). 저장소가 공개라 창 제목·요소 이름은 지웠고, 파일 이름이 들어가는 `logs/point_trace.jsonl`과 96 MB 표본 저장소(`data/online/samples`)는 올리지 않았다.

| 폴더 | 내용 | 되살리는 법 |
|---|---|---|
| `use_events/` | 사용 기록(`.jsonl.gz`로 압축) + 색인 + `reviews.json` | 압축을 풀어 `logs/use_events/`에 |
| `failures/` | 실패 기록 200개(닫기 대상 창 정보와 요소 이름은 지움) | 그대로 분석용 |
| `composite_fires/`, `virtual_clicks/` | 복합 동작 실행 직전 관절, 가상 손 클릭 기록 | 분석용 |
| `online/` | `data/online`의 모델·상태 파일(표본 저장소 제외) | 새 폴더에서는 `scripts/online_make_base.py`로 기본 모델부터 다시 만드는 편이 안전 |
| `onnx_candidate/` | 첫 onnx 후보와 `summary.json` | `models/candidate/`에 두면 앱에서 [새 모델 확인] |

이 PC의 수치: 좌클릭 194개가 검토를 기다림(통과 0), 손 펴기 유지·위쪽은 통과 21·오탐지 17(확인 모델은 다른 날 사용을 기다리는 중), 우클릭 표시 34개.

첫 onnx 후보: 따로 둔 오탐지 10개 중 손짓으로 본 것이 지금 모델 8개 → 후보 1개. **아직 적용하지 않았다.** 후보의 빠른 검사 수치(엄지+검지 81%, 이동 오작동 4.6회/분)는 지금 모델의 꼼꼼 검사 수치(94%, 2.3회/분)와 방식이 달라 직접 비교할 수 없다.

## 5. 확인하지 못한 것 (사용자에게 그대로 말할 것)

- 이 세션의 수정 대부분은 **실제 카메라로 써 본 결과를 듣지 못했다**. 시험(가짜 손), 기록 재생, 화면 밖 렌더링으로만 확인했다.
- 앱이 `online_make_base.py`·`onnx_auto_update.py`를 실제로 띄우는 것(스크립트 자체는 끝까지 돌려 확인).
- 학습 중 앱을 꺼서 다시 시작되는 것.
- onnx 후보를 적용한 뒤의 체감, [이전 모델로 되돌리기].
- 메인 창 "항상 위"를 무엇이 붙이는지(추정: Win+D의 바탕화면 보기 상태). `logs/topmost_fixes.log`의 시각을 Win+D 실행 시각과 맞춰 볼 것.
- 전체 시험은 1,162개 통과(Windows)지만, 가끔 Qt access violation으로 프로세스가 멈춘다(재실행하면 통과). `test_sequence`의 3초짜리 시간 시험도 전체 실행에서 한 번 실패한 적이 있다.

## 6. 다음 할 일 (우선순위 순)

1. 사용자가 좌클릭 사례를 검토하면 onnx 후보에 "통과한 클릭"이 처음 들어간다. 그 후보에서 엄지+검지 인식이 떨어지지 않는지 볼 것(지금 후보는 오탐지만 배워 인식이 84% → 81%).
2. **(2026-11-12 오전에 함: CLAUDE.md "onnx 후보 옆에 같은 방식의 기준")** onnx 후보 검사를 더 믿을 만하게: 빠른 검사는 자세 하나(엄지+검지·엄지+약지만)라 다른 동작이 나빠져도 모른다. 같은 방식의 기준 수치(사용 사례 없이 학습)를 한 번 만들어 `summary.json`에 나란히 넣는 것이 다음 단계.
3. 자동 수집 데이터가 onnx에 들어가는 범위 넓히기: 지금은 클릭과 오탐지뿐. 스크롤 잡기(`scroll_grab`)·끌기 등 다른 규칙 명령은 검토 화면이 없어 들어가지 않는다.
4. 진짜 중간 저장: pt 회차는 53초(갱신 3초)라 필요 없다고 판단했다. onnx 후보 학습은 6~8분이라 끊김이 잦으면 의미가 있다. 지금은 평가 겹 단위(`--resume`)까지만 이어진다.
5. 손등 판정에서 손 인식이 반대 손으로 표시해 조작 손에서 빠지는 경우를 팔 정보로 살리기(안 함).

## 7. 일하는 방식 메모

- 사용자의 Windows 사용자 폴더 이름·실제 PC 이름은 저장소에 적지 않는다(공개 저장소).
- 값 수정은 기본 상태(코드 기본값·공통 설정 파일)를 고친다. 프로필 파일은 요청이 있을 때만.
- 사용자는 "올려"라고 할 때만 커밋·푸시를 원한다. 보고는 바뀐 것 / 확인 방법 / 시험하지 못한 것.
- 동기화: `uv sync --locked --extra qt --extra train --extra llm`. 시험: `.venv\\Scripts\\python.exe -m pytest -q`.
